# Deploying on Render

`render.yaml` describes the whole setup, all in Render's **Frankfurt (EU)** region:

| Resource | What it is | Plan in `render.yaml` |
|---|---|---|
| `euaiact` | Web app (Docker), HTTPS provided by Render | `starter` |
| `euaiact-refresh` | Daily job at 06:00 UTC: refresh assignments and send reminder e-mails | `starter` (billed only while it runs) |
| `euaiact-db` | PostgreSQL 16 database | `basic-256mb` |

Check the current prices on Render's pricing page before you create anything. Don't use the
free plans: free web services go to sleep when idle, and free databases are deleted after a
trial period, which would lose your evidence register.

## Free demo (try it first)

`render-free.yaml` creates a **free** demo: the web app plus a free PostgreSQL database, with
fictional sample data (`EUAIACT_DEMO=1`) and a "demo, no real data" banner. It has no
scheduled job and needs no settings.

1. Sign in at render.com with your GitHub account.
2. **New > Blueprint**, select `paola-grx/EUAIACT`, branch `main`, and set **Blueprint Path**
   to `render-free.yaml`.
3. Click **Apply** and wait for the first build (a few minutes).
4. Open the address of `euaiact-demo` (e.g. `https://euaiact-demo.onrender.com`), create
   the administrator, and complete the onboarding. The dashboard, people, AI systems and
   evidence register already contain sample data.

If your Render screen has no Blueprint Path field, create the two parts by hand:
**New > Postgres** (Free, Frankfurt), then **New > Web Service** from the repository
(Docker, Free, Frankfurt, health check path `/healthz`) with these environment variables:
`EUAIACT_ENV=production`, `EUAIACT_DEMO=1`, a random `EUAIACT_SECRET_KEY` of at least 32
characters, and `EUAIACT_DATABASE_URL` set to the database's *Internal Database URL*.

**Free-plan limits:**
- The app sleeps after about 15 minutes without visitors, and the next visit takes about
  a minute to wake it.
- The free database expires after a trial period (check Render's current terms). Once it
  has expired, delete the demo, or move to the paid setup below.
- There are no free scheduled jobs: use **Settings > Run refresh cycle now** in the app.
- Never put real staff data into the demo.

When you are happy with it, delete the demo resources in Render and follow the paid setup
below. The resource names differ, so both setups can exist side by side.

## 1. Create the Blueprint

1. Sign in at render.com with your GitHub account.
2. **New > Blueprint** and select the `paola-grx/EUAIACT` repository, branch `main`.
3. Render reads `render.yaml` and lists the three resources. It asks for the values marked
   `sync: false`:
   - **EUAIACT_BASE_URL** (required): the public address of the app. For the first deploy,
     enter `https://euaiact.onrender.com`. If Render gives the service a different address
     (for example with a suffix, because the name is taken), change this value afterwards
     (step 3).
   - **SMTP settings** (optional): leave them empty for now if you don't have a mail server
     yet. Reminders then stay queued in the app. `EUAIACT_SMTP_FROM` must be filled in
     whenever `EUAIACT_SMTP_HOST` is set.
4. Click **Apply**. The first build takes a few minutes.

`EUAIACT_SECRET_KEY` is generated by Render. `EUAIACT_DATABASE_URL` is wired to the
database automatically.

## 2. First login

1. Open the web service's address (shown at the top of the `euaiact` service page).
2. The first visit shows **Set up**: create the first administrator. Do this straight
   away, because until an administrator exists, anyone who opens the address can create one.
3. Complete the app onboarding, which is required for every admin and reviewer.

## 3. Check the address

If the address Render shows differs from what you entered for `EUAIACT_BASE_URL`, go to
**Environment Groups > euaiact-shared** and correct it. Save, then redeploy both services.
The daily job needs this value, because reminder e-mails contain personal learning links.

## 4. Custom domain (optional)

1. In the `euaiact` service: **Settings > Custom Domains**, add e.g. `ai-literacy.example.eu`,
   and create the DNS record Render shows.
2. Set `EUAIACT_BASE_URL` to `https://ai-literacy.example.eu` in the environment group and
   redeploy.
3. Update the "See the full tool" link on the Lovable site to the new address.

## 5. E-mail reminders (optional)

Set the SMTP values in the `euaiact-shared` environment group. Use the credentials from
your mail provider, for example your organisation's mail server or a transactional
service. Port 587 with `starttls` is the usual choice. Then use **Settings > Send queued
reminders** in the app to test.

## Backups and data

- Paid Render PostgreSQL plans include automatic backups. Check the retention period
  for your plan.
- The database holds personal data (staff names, e-mail addresses and training history).
  Record Render as a processor in your GDPR records and sign Render's data processing
  agreement.
- The app's database role owns its tables, so it could in principle disable the
  append-only triggers. The hash chain would still reveal any tampering (see the
  dashboard's integrity check).

## Troubleshooting

- **The deploy fails with "Unsafe production configuration":** the message names the
  missing setting. The most common cause is `EUAIACT_BASE_URL` being empty or not `https://`.
- **The health check fails:** the service is checked at `/healthz`, which also tests the
  database connection. Check the database is available and the service logs.
- **Render rejects `render.yaml`:** Render validates the file on import and names the
  field. Render occasionally renames plans; pick the nearest paid plan in the dashboard.
